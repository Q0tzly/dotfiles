# グローバル指示

Claude Code と Codex が全セッションで読み込む個人指示（dotfiles の `ai/AGENTS.md`。`~/.claude/CLAUDE.md` と `~/.codex/AGENTS.md` はここへのリンク）。
プロジェクト固有のことは各リポジトリの `CLAUDE.md` / `AGENTS.md` に書く。

## 言語・トーン

- 応答は日本語。コード内のコメント・識別子は英語のまま。
- 不要な前置きや結論の繰り返しは省く。簡潔に。
- 「やりました」「完了しました」のような決め台詞よりも、何が変わって次に何をするかを 1〜2 文で。

## 作業の進め方

- 推測で作業せず、不明点は早めに聞く。ただし軽微な選択は自分で判断して進める。
- 既存ファイルの編集を優先。新規ファイルは必要なときだけ。
- 変更は小さく刻む。一度に複数の関心事を混ぜない。
- 動作未確認のものを「動く」と言わない。試したか／試していないかを明示する。

## コードスタイル

- コメントは「なぜ」を書く必要があるときだけ。「何をしているか」は識別子で表現する。
- 後方互換のための半端なシム・未使用変数のリネーム（`_var`）を残さない。不要なら削除。
- エラーハンドリングは境界（外部 API・ユーザー入力）でだけ。内側で防御的に書かない。

## Git

- コミットは適宜作る。1 つの変更がまとまった時点で都度切る。あとでまとめてではなく、その場で。
- `--no-verify`、`--force` は明示の許可なしで使わない。
- 破壊的操作（reset --hard、branch -D、push --force）は必ず確認を取る。

## バージョン管理

- `Cargo.toml` / `package.json` / `pyproject.toml` などのバージョンは、変更内容に応じて適宜上げる。聞かずに上げてよい。
- 上げ方は semver に従う:
  - **patch** (`0.1.0` → `0.1.1`): バグ修正、内部リファクタ
  - **minor** (`0.1.0` → `0.2.0`): 後方互換のある機能追加
  - **major** (`0.1.0` → `1.0.0`): 破壊的変更
- 0.x 系では minor を「破壊的変更」として扱う慣習があるので、その場合は patch / minor を 1 段ずらして適用する。
- バージョン更新は機能変更と同じコミットに含める（別コミットにしない）。

## ツール使い分け

- ファイル探索は速い方を選ぶ。デフォルトは ripgrep (`rg`) / `fd`（`grep` / `find` より速い）だが、より効率的な手段（IDE のインデックス、専用 CLI、プロジェクト固有の検索スクリプト等）があればそちらを優先。
- 広範な調査だけサブエージェント（Claude Code の Explore など）に任せる。
- 並列化できるツール呼び出しは同じメッセージ内でまとめて呼ぶ。

## タスクの順序（許可待ちで止まらない）

着手前にタスクを「許可不要」「許可必要」の 2 群に分け、許可不要のものから片付ける。

- **許可不要の例**: 既存ファイルの編集、ファイルの読み取り・検索、ローカルでのテスト実行、`git status` / `git diff` / `git log`
- **許可必要の例**: 新規パッケージのインストール、外部 API 呼び出し、`git push`、`gh pr create`、本番への反映

判断方針:

- 許可が必要そうなタスクは、可能な限り後ろにまとめる。途中で個別に聞かない。
- 1 つの許可待ちで他のタスクが止まらないよう、独立して進められるものを先に終わらせる。
- 最後に「許可が必要なものリスト」をまとめて提示し、一度に承認してもらう。

## 自走モード（夜間 / 就寝後）

以下のいずれかに該当するときは、選択判断をユーザーに聞かずに自分で決めて作業を進める。
朝に結果を確認できるよう、判断した内容と理由を簡潔に残す。

- **時間帯**: 1:00〜8:00
- **明示トリガー**: ユーザーが「寝る」「寝るわ」「おやすみ」等を発したあと（次の対話で解除）

### 自走中の許可必要タスクの扱い

- 許可が必要なタスクは**実行せずスキップ**し、許可不要のもので進められる分は全部終わらせる。
- スキップしたものは「保留タスク」として理由とともに記録する。
- 朝の引き継ぎで、保留タスク一覧を出して判断を仰ぐ。

### 自走中でも必ず止まる例外（スキップではなく停止）

- **破壊的操作**: `reset --hard`、`push --force`、`branch -D`、本番反映、データ削除など
- **課金が発生する操作**: クラウドリソース作成、有料 API の大量呼び出しなど

これらは「やるかやらないか」自体を朝に判断してもらう必要があるので、関連する周辺タスクも巻き込んで止める。

## rtk

- `rtk` が PATH にあれば、シェルコマンドは `rtk` 経由で実行する（出力が圧縮されてトークンが減る）。
- Claude Code はフックが自動で書き換えるので何もしなくてよい。それ以外のエージェントは `rtk git status` のように自分で前に付ける。
- 生の出力が要るときは `rtk proxy <cmd>`。

## Flash への実装委任

原則は自分で実装する。複数ファイルにまたがる新規実装で、作業票（触るファイル・インターフェース・合格条件）が事前に書け、失敗しても diff を捨てるだけで済むときだけ、`subcon submit` で Gemini Flash に渡す。
委任する前に `subcon guide` を読み、その手順（作業票の書式・検収・コミットの trailer）に従う。
